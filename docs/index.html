01

Chain kernels in the hot loop

Every function comes in f32 and f64 via family submodules. The allocation-free _into forms reuse one buffer set across calls — here a transformer-style activation path: 

use lanes::ml::f32;

let hidden = vec![0.5_f32; 512]; // activations in
let mut normed    = vec![0.0_f32; 512];
let mut activated = vec![0.0_f32; 512];
let mut probs     = vec![0.0_f32; 512];

f32::layer_norm_into(&hidden, 1e-5, &mut normed).unwrap();
f32::gelu_into(&normed, &mut activated).unwrap();
f32::softmax_into(&activated, &mut probs).unwrap();
// `probs` is a valid distribution — three SIMD kernels, zero per-call
// allocations, one backend picked at startup.

Every public function, measured

f32, n = 65 536, AVX-512F backend on an i5-1135G7, release build. “naive” is the plain iterator expression compiled with identical settings. Reproduce with cargo run --release --example readme_bench_all.

familyfunctionlanesnaivespeedup

Want the picture? Interactive charts — speedup bars, a log-scale regime map, and the erf accuracy curve, all filterable.

Two regimes, read honestly. Reductions and transcendentals win 3–25×: LLVM can’t auto-vectorize FP reductions without fast-math, so the naive baseline stays scalar, and compute-heavy maps are dominated by vectorized polynomial approximations. Trivial elementwise ops (relu, clip, sqrt) sit at ~1× because the compiler auto-vectorizes the baseline too — both are memory-bandwidth bound. erf/erfc have no std baseline: their naive column is the Abramowitz–Stegun 7.1.26 polynomial, a speed reference of a far less accurate algorithm, and the bench distribution is tail-heavy, where lanes pays two correctly-rounded vector exps to hold its accuracy contract (2–3× faster on small/mid-heavy inputs).

04

Runtime dispatch, zero ceremony

Detection runs once and is cached in a OnceLock — dispatch overhead after the first call is a single load. Unsafe SIMD code is isolated in the kernel layer behind platform::supports gates; the algorithm layer is #![forbid(unsafe_code)].

Force a backend: LANES_BACKEND=scalar|sse2|avx2|avx512|neon pins it for benchmarking or debugging; cargo run --example dispatch_info prints what was detected and why. no_std: without std the architecture-guaranteed tier is picked statically — SSE2 on x86-64, NEON on aarch64, scalar elsewhere. default-features = false, add alloc for the Vec-returning families.

05

The accuracy contract

Measured against std and arbitrary-precision oracles on every backend — not just the fast path.

Transcendentals — ≤ 1 ulp
exp, ln, tanh, sqrt, rsqrt — ≤ 1 ulp vs std (fdlibm/SLEEF/musl-derived reductions), on every backend.
Specials — perfectly rounded (f32)
erf ≤ 1 ulp (f64), erfc ≤ 3 ulp (f64 — the structural floor of the exp-product tail form); both perfectly rounded in f32. Clean-room Remez coefficients.
Overflow-safe hypot
Scales by max(|a|, |b|); 1–2 ulp vs std::hypot, identical NaN/inf propagation. powi is bit-exact with std::powi, including specials.
Uniform NaN rules
sum/dot propagate NaN; min/max follow IEEE 754 minNum/maxNum; max_norm returns NaN if any input is NaN. Reduction order is backend-dependent: deterministic within a backend, last-ulp differences across backends.
06

Nothing panics

Fallible kernels return Result<_, lanes::Error>. Infallible kernels (reductions like sum, single-input maps like exp) never fail.

Unequal operand lengths — dot, squared_distance, abs_sub, hypot, cosine_similarity, kl_divergence, js_divergence, hamming, jaccardError::LengthMismatch { expected, actual }
